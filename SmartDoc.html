1. 🧱 Créer le projet

Nom proposé : Proto Claude SmartDoc

Prompt — Instructions projet

Ce projet sert à prototyper le classement, l'indexation et l'interrogation d'un fonds documentaire.

Contexte de travail :
- stockage : {{storage}}, via {{connector}} ;
- dossier source, où arrivent les documents en vrac : "{{src}}" ;
- dossier cible, où le fonds sera rangé : "{{dst}}" ;
- registre : un fichier Excel "{{fileName}}" à la racine du dossier cible "{{dst}}".

Règles générales :
- l'IA propose, l'humain dispose : aucune action sur les fichiers sans ma validation explicite ;
- le dossier source "{{src}}" est en lecture seule : ne jamais y supprimer, déplacer ni renommer quoi que ce soit ;
- le classement se fait uniquement par COPIE vers "{{dst}}" ; l'original reste toujours en place ;
- ne jamais {{action}} un fichier avant que j'aie validé le lot ;
- ne jamais modifier le contenu d'un document source ;
- ne jamais inventer une métadonnée : laisser vide ou écrire unknown ;
- ne jamais inscrire une date qui n'est pas explicitement présente dans le document ou dans le nom du fichier ;
- toute affirmation sur le fonds doit être sourcée : nom du fichier, et page quand la pagination existe ;
- travailler par étapes simples, une étape à la fois ;
- tenir le fichier Excel comme mémoire documentaire ;
- dans le fichier Excel, écrire en anglais les noms d'onglets, les noms de colonnes et les codes, c'est-à-dire les valeurs fermées comme status, confidence ou la profondeur d'indexation ; écrire en français les textes libres, comme summary ou tags, ainsi que les catégories, qui nomment les dossiers de "{{dst}}" ;
- ne pas créer de {{cloudAlt}} ;
- ne définir aucun plan de classement pour l'instant : nous le déciderons ensemble à l'étape 5 ;
- pour cette formation, limiter le traitement à 20 documents ; le volume de production sera fixé à l'étape 12 ;
- produire un rapport court à la fin de chaque étape ;
- ne créer la Skill métier qu'après plusieurs étapes testées dans ce fil ;
- créer la tâche planifiée seulement après validation du workflow et de la Skill métier.

4. 🔎 Inventorier le fonds et repérer les doublons

Objectif : cartographier "{{src}}", créer une ligne par document et repérer doublons et fichiers inutiles, sans rien déranger.

Prompt — Inventaire, cartographie et doublons

Inventorie le contenu du dossier "{{src}}" via {{connector}}, puis repère les doublons. Aucun fichier ne bouge à cette étape.

Pour cette formation, limite-toi à 20 documents. Les suivants seront traités par la tâche planifiée de l'étape 12.

Phase 1 — Inventaire et cartographie :
Ajoute une ligne par fichier dans l'onglet "register" du fichier "{{fileName}}" :
- file_name ;
- detected_date, uniquement si une date est explicitement présente dans le nom du fichier ou dans le document ;
- date_source = document / filename / unknown ;
- status = to_analyze.

Laisse vides pour l'instant : category, proposed_name, target_path, summary, tags, source_reference. duplicate_status et confidence seront renseignés à la phase 2.

Produis ensuite une cartographie du fonds dans le chat :
- nombre total de fichiers ;
- répartition par format ;
- répartition par type apparent de document ;
- nombre de fichiers avec une date explicite ;
- nombre de fichiers sans date ;
- volume total ;
- anomalies repérées : fichiers vides, illisibles, hors périmètre.

Phase 2 — Doublons et fichiers inutiles :
Sur ce même lot, identifie :

1. Les doublons exacts :
- fichiers identiques par nom et par contenu ;
- fichiers identiques par contenu mais avec un nom différent.

2. Les doublons probables :
- fichiers très similaires : versions successives, brouillons, copies partielles.

3. Les fichiers problématiques :
- fichiers vides ;
- fichiers illisibles ;
- fichiers hors périmètre documentaire.

Mets à jour uniquement, dans "{{fileName}}" :
- duplicate_status = unique / exact_duplicate / possible_duplicate ;
- confidence = high / medium / low ;
- status = ignored pour les fichiers vides, illisibles ou hors périmètre.

Présente ensuite la liste des cas détectés, regroupés par paire ou par groupe, avec pour chacun :
- les fichiers concernés ;
- le motif du rapprochement ;
- ton niveau de confiance.

Règles :
- ne supprime aucun fichier ;
- ne {{actionImp}} aucun fichier et ne renomme rien ;
- ne propose aucun plan de classement : le sort des doublons sera décidé à l'étape suivante ;
- ne crée pas de {{cloudAlt}}.

5. 🗂️ Décider le plan de classement

Le cœur du dispositif : Claude pose huit questions construites sur vos fichiers réels, vous choisissez, et le plan retenu pilote tout le reste de la formation.

Prompt — Élicitation en 8 questions

Nous allons définir ensemble le plan de classement du fonds. Ne propose aucun plan avant d'avoir mes réponses.

Phase 1 — Élicitation, obligatoire :
À partir de l'inventaire et des doublons que tu viens d'analyser, pose-moi les 8 questions ci-dessous.

Règles de la phase 1 :
- utilise ton interface de choix cliquables, par groupes de 4 questions ;
- si tu ne peux pas afficher de choix cliquables, pose les 8 questions numérotées dans un seul message avec des options a / b / c, et je répondrai en une ligne du type "1b 2a 3c 4a 5b 6a 7ac 8b" ;
- pour chaque question, propose 2 à 4 options concrètes construites sur MES fichiers, en citant des exemples réels de l'inventaire et les décomptes correspondants ;
- indique à chaque fois l'option que tu recommandes, et pourquoi ;
- n'ajoute aucune question, n'en saute aucune ;
- attends mes réponses avant de passer à la phase 2.

Les 8 questions :
1. Axe principal de rangement : par nature de document, par thème, par auteur ou émetteur, par période, ou par projet et client ? Cet axe déterminera les dossiers de premier niveau dans "{{dst}}".
2. Axe secondaire, pour les sous-dossiers : année, thème, auteur, ou aucun sous-niveau ?
3. Granularité : 3 à 5 catégories larges, 6 à 10 catégories, ou davantage ? Propose le découpage correspondant à partir de ce que tu as vu. Les catégories sont en français : elles nommeront les dossiers de "{{dst}}".
4. Convention de nommage des fichiers : YYYY-MM-DD_Auteur_Sujet, ou Sujet-court seul, ou conserver les noms d'origine ? Illustre chaque option sur un fichier réel de l'inventaire.
5. Documents sans date certaine : copiés dans un sous-dossier "À dater", copiés sans date dans leur catégorie, ou pas encore copiés en attendant que la date soit tranchée ?
6. Doublons et fichiers inutiles : ne copier qu'une seule version dans "{{dst}}", copier toutes les versions en les distinguant, ou ne rien copier et se contenter de les signaler dans le registre ?
7. Axes que je veux pouvoir interroger plus tard, plusieurs réponses possibles : personnes citées, lieux, concepts, auteur ou organisme, client ou projet, niveau de confidentialité ?
8. Profondeur d'indexation : résumé d'une ligne (code one_line_summary), résumé et mots-clés (code summary_tags), ou résumé, mots-clés, entités et citation sourcée (code full_index) ? Inscris dans le plan le code retenu, tel quel : l'étape 7 s'y référera.

Phase 2 — Récapitulatif :
Présente-moi un récapitulatif clair de mes 8 choix, comprenant :
- la liste définitive des valeurs autorisées de category ;
- l'arborescence exacte qui sera créée dans "{{dst}}" ;
- la règle de nommage retenue, illustrée sur trois fichiers réels de l'inventaire ;
- le code de profondeur d'indexation retenu ;
- la liste des colonnes supplémentaires qui seront ajoutées au registre.
Demande-moi ensuite une validation explicite. N'écris rien dans le registre avant de l'avoir reçue.

Phase 3 — Enregistrement, après ma validation seulement :
- inscris les 8 questions, mes réponses et les valeurs retenues dans l'onglet "classification_plan" de "{{fileName}}" ;
- ajoute à l'onglet "register" les colonnes correspondant à ma réponse à la question 7, dans la limite de 5 colonnes, avec des noms en anglais.

Confirme-moi ensuite ce qui a réellement été écrit dans l'onglet : la liste des catégories, l'arborescence, la règle de nommage et les colonnes ajoutées. Précise que c'est ce plan, et lui seul, qui pilotera l'étape 6.

Ne {{actionImp}} aucun fichier.
Ne renomme rien.
Ne crée aucun dossier à ce stade.

6. 🏷️ Classer et ranger le fonds

Claude propose un classement conforme au plan, puis range le fonds dans "{{dst}}" : la seule étape où les fichiers bougent réellement, et uniquement après votre validation du lot.

Prompt — Proposition, validation et rangement

Phase 1 — Relecture du plan, obligatoire :
Relis l'onglet "classification_plan" du registre "{{fileName}}" et rappelle-moi en trois lignes ce que tu y trouves :
- la liste des catégories autorisées ;
- l'arborescence à créer dans "{{dst}}" ;
- la règle de nommage retenue.

Si cet onglet est vide ou introuvable, arrête-toi et dis-le-moi : ne propose aucun classement sans plan validé, et ne rejoue pas l'élicitation de ta propre initiative.

Phase 2 — Proposition de classement :
Pour chaque ligne du registre "{{fileName}}" dont status = to_analyze, prépare une proposition de classement conforme à ce plan. Ne t'écarte jamais de ce qui y est inscrit.

Renseigne uniquement :
- category : obligatoirement une des valeurs définies dans le plan validé ;
- proposed_name : selon la convention de nommage validée ;
- target_path : "{{dst}}" suivi de l'arborescence validée ;
- confidence = high / medium / low ;
- status = proposed.

Règles de la phase 2 :
- n'utilise une date dans le nom que si elle est explicitement présente dans le document ou dans le nom du fichier ;
- applique aux documents sans date la règle validée à la question 5 ;
- applique aux doublons la règle validée à la question 6 ;
- ne crée aucune catégorie en dehors du plan validé ;
- ne renomme aucun fichier et ne {{actionImp}} aucun fichier : tout n'est que proposition.

Présente ensuite un tableau dans le chat :
nom actuel → catégorie → nom proposé → destination → justification courte → confiance

Liste enfin séparément les documents que tu n'arrives pas à dater ou à qualifier, et pose-moi 2 à 3 questions ciblées pour les trancher.

Phase 3 — Validation du lot, point d'arrêt obligatoire :
Rappelle-moi le lot : nombre de documents en status = proposed, répartition par category, nombre de cas en confidence = low.
Puis arrête-toi. Attends mes réponses aux questions et ma validation explicite du lot. Sans validation de ma part, ne touche à aucun fichier.

Phase 4 — Rangement, après ma validation seulement :
- crée dans "{{dst}}" les sous-dossiers de l'arborescence validée ;
- {{actionImp}} vers target_path chaque document approuvé, avec son proposed_name ;
- applique la règle validée à la question 5 pour les documents sans date ;
- applique la règle validée à la question 6 pour les doublons et les fichiers inutiles ;
- passe status = classified sur les documents traités ;
- passe status = needs_review pour les documents en confidence = low ou que j'ai écartés : ne les copie pas.

Règles de la phase 4 :
- le dossier source "{{src}}" ne doit être modifié en aucune façon : rien de supprimé, rien de déplacé, rien de renommé ;
- le renommage ne s'applique qu'à la COPIE déposée dans "{{dst}}" ;
- ne modifie jamais le contenu d'un document ;
- {{afterAction}}.

À la fin, indique :
- nombre de documents {{actionPast}} dans "{{dst}}" ;
- répartition par category ;
- nombre de documents laissés en needs_review, et pourquoi ;
- erreurs rencontrées ;
- actions humaines restantes.

7. 🔖 Indexer en profondeur

L'ampleur de cette étape dépend entièrement de la profondeur d'indexation choisie à l'étape 5.

Prompt — Indexation profonde

Étape préalable, obligatoire :
Relis l'onglet "classification_plan" du registre "{{fileName}}" et rappelle-moi en deux lignes :
- le code de profondeur d'indexation retenu à la question 8 ;
- les colonnes supplémentaires retenues à la question 7, telles qu'elles existent réellement dans l'onglet "register".

Si cet onglet est vide ou introuvable, arrête-toi et dis-le-moi : n'invente aucune profondeur d'indexation et ne rejoue pas l'élicitation de ta propre initiative.

Ensuite seulement :
Enrichis le registre pour chaque document dont status = classified dans "{{fileName}}".

Renseigne exactement ce que la profondeur retenue impose, et rien de plus :
- one_line_summary : summary seul, en une phrase ;
- summary_tags : summary de 2 à 3 phrases, et tags ;
- full_index : summary de 2 à 3 phrases, tags, et les colonnes retenues à la question 7.

Deux colonnes se renseignent dans tous les cas, quelle que soit la profondeur retenue :
- source_reference : nom du fichier et page quand la pagination existe, sinon nom du fichier et section ou extrait repérable. Sans elle, aucune réponse ne pourrait être sourcée à l'étape 8 ;
- confidence : ton niveau de certitude sur l'indexation de cette ligne.

Précisions sur les autres colonnes :
- summary : un chapeau analytique qui dit de quoi le document traite réellement ;
- tags : mots-clés thématiques tirés du contenu réel, pas de vocabulaire générique.

Règles :
- ne remplis que les colonnes qui existent déjà dans le registre : n'en crée aucune ;
- ne remplis aucune colonne que la profondeur retenue n'exige pas, même si tu saurais le faire ;
- ne jamais inventer une information absente : laisser vide ou écrire unknown ;
- ne jamais déduire une date par rapprochement ; detected_date ne se remplit que si la date est explicite dans le document ou son nom ;
- ne pas modifier le contenu des documents ;
- pour cette formation, limite-toi à 20 documents.

À la fin, indique le nombre de lignes enrichies, les colonnes réellement remplies, et la liste des documents dont l'indexation reste incertaine.

Soumets-moi ensuite 3 à 5 résumés — les plus représentatifs et ceux dont tu es le moins sûr — pour que je valide ou corrige leur pertinence. Applique mes corrections au registre avant de conclure l'étape.

8. 💬 Interroger le fonds et générer le rapport PDF

Le registre devient la mémoire de Claude, et le rapport PDF restitue à la fois l'état du fonds et ce qu'il contient.

Prompt — Questions au fonds et rapport PDF

Le registre "{{fileName}}" est désormais ta mémoire documentaire. Utilise-le pour répondre, sans rien inventer.

PREMIÈRE PARTIE — interroge le fonds.

Réponds aux questions suivantes en citant systématiquement tes sources : nom du fichier, et page quand elle existe.

1. Quels documents du fonds traitent de : {{topic}} ?
2. Quels thèmes reviennent le plus souvent, comment évoluent-ils dans le temps, et y a-t-il une période plus dense que les autres ?
3. Quelles personnes, quels auteurs ou quels interlocuteurs reviennent le plus, et lesquels apparaissent souvent ensemble ?
4. Qu'est-ce que ce fonds ne contient pas, alors qu'on s'y attendrait ?

Règles :
- appuie chaque affirmation sur des lignes précises du registre ;
- si le registre ne suffit pas pour répondre, dis-le explicitement au lieu de combler ;
- distingue clairement ce que le fonds démontre de ce qu'il suggère ;
- les documents sans date certaine ne sont jamais placés arbitrairement dans une chronologie ;
- ne modifie pas le registre.

SECONDE PARTIE — produis le rapport.

Génère ensuite un seul rapport PDF, en deux sections.

Section 1, état du fonds :
- date du rapport et périmètre analysé ;
- nombre total de documents traités ;
- répartition par category et par status ;
- nombre de documents sans date explicite ;
- doublons détectés et sort qui leur a été réservé ;
- documents en needs_review et motif ;
- actions humaines restantes.

Section 2, contenu du fonds :
- les grands thèmes et leur poids relatif ;
- l'évolution des thèmes et des concepts dans le temps, quand les dates le permettent ;
- les auteurs, personnes ou interlocuteurs récurrents, et ceux qui apparaissent ensemble ;
- 3 à 5 documents représentatifs, avec un résumé d'une phrase chacun ;
- ce que le fonds ne couvre pas ou couvre mal.

Règles :
- ne jamais inclure le contenu complet d'un document ;
- ne pas inventer de chiffre : tout doit provenir du registre ;
- chaque affirmation renvoie aux documents qui la fondent, par leur nom de fichier ;
- les documents sans date certaine figurent à part, jamais placés arbitrairement dans une chronologie ;
- signaler les données insuffisantes plutôt que compléter par des contenus inventés ;
- sauvegarder le PDF à la racine de "{{dst}}" et indiquer son chemin.
